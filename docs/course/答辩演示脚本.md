# ChatPulse 课程答辩演示脚本（约 15 分钟）

> 配合《软件架构与应用开发实践》现场检查使用。现场检查权重：架构设计方案 0.5 / 软件文档 0.2 / 原型系统 0.3。

## 演示前准备（提前 30 分钟）

```bash
# 1. 在 Ubuntu 虚拟机执行
docker compose down -v && docker compose up -d    # 全新环境启动 17 个容器
docker compose ps                                  # 确认全部 Up（约需 2-3 分钟）

# 2. 验证就绪
curl http://127.0.0.1:8080/health                  # Nginx: OK
curl http://127.0.0.1:8000/api/health              # Bridge: {"status":"ok",...}

# 3. 打开浏览器 http://localhost:3000 并预先登录 admin/admin123（预置账号）
# 4. 准备第二个浏览器窗口（普通模式）演示多用户
```

## 演示流程

### 第一幕：系统概览与架构（3 分钟，对应"架构设计方案检查"）

1. 打开 `docs/course/实习实训报告-ChatPulse集群智能聊天服务器.md`，展示：
   - 第 6.1 节总体架构图（五层：用户/接入/服务/AI/数据）
   - 第 6.3 节物理拓扑图（17 容器分布）
2. 终端执行 `docker compose ps`，对照"容器→架构层次"讲解：
   > "三个 ChatServer 是服务层，Nginx 做负载均衡；MySQL 一主两从和 Redis 哨兵在数据层；
   > Kafka 负责跨服务器消息广播；Bridge 和 Agent 是接入层与 AI 层。"
3. 展示第 9 节非功能设计：高并发（负载均衡+缓存+读写分离）、高可用（主从+哨兵+多实例）、
   高可扩展（实例端口即消费组后缀，加容器即扩容）。

### 第二幕：核心功能演示（6 分钟，对应"软件原型系统开发"）

| 序号 | 操作 | 预期 | 对应功能点 |
|------|------|------|-----------|
| 1 | 窗口 A 注册新账号 | 提示获得新 ID | 用户注册（UC-001） |
| 2 | 窗口 A 登录 | 好友列表自动含"AI智能助手" | 登录（UC-002）+ 自动好友 |
| 3 | 窗口 B 用 admin 登录 | 在线状态点变绿 | 在线状态 |
| 4 | A 给 admin 发消息 | B 实时收到（WebSocket 推送） | 私聊（UC-004） |
| 5 | A 加入公共聊天室发言 | 两个窗口都收到 | 群聊（UC-005） |
| 6 | A 创建群组 | 侧边栏**无需重新登录**即出现新群 | 建群（UC-007）+ /api/refresh |
| 7 | A 对 AI 说"帮我看看好友列表" | AI 调用 MCP 返回好友 | AI 工具调用（UC-010） |
| 8 | A 让 AI "给 admin 发一条消息" | admin 收到 AI 代发消息 | AI 代发 |
| 9 | 退出 A，B 给 A 发消息，A 重新登录 | 登录即收到离线消息 | 离线消息（UC-011） |
| 10 | A 打开与 B 的聊天窗口 | 自动加载 100 条历史消息 | 历史查询（UC-009） |

> 小技巧：AI 回复建议准备一条固定话术（如"帮我看看在线用户"），避免现场等 LLM 响应过久；
> 未配置 API Key 时 Agent 走 Dummy 模型也能完整演示对话流程。

### 第三幕：集群与容错（4 分钟，对应"高可用/高可扩展"主张）

1. **跨服务器消息**（展示 Kafka 路由）：
   ```bash
   # 让 admin（在 Server1 通过 Nginx 进入）与另一账号通信时观察日志：
   docker compose logs chat_server_1 | grep -i kafka      # 生产者
   docker compose logs chat_server_2 | grep -i "deliver"  # 消费者投递
   ```
2. **故障容错**（演示 Nginx 剔除 + 服务不中断）：
   ```bash
   docker compose stop chat_server_1      # 停掉一个服务器
   # 浏览器继续发消息 —— 连接经 Nginx 被分发到 Server2/3，聊天不中断
   docker compose ps                      # nginx 显示 chat_server_1 被摘除
   docker compose start chat_server_1     # 恢复
   ```
3. **主从复制验证**：
   ```bash
   docker exec chat_mysql_slave1 mysql -uchatuser -pchatpass123 chat -e "select count(*) from user;"
   # 与主库数量一致即复制正常
   ```

## 常见被问问题与回答要点

| 问题 | 回答要点 |
|------|----------|
| 为什么用 Kafka 而不是 Redis Pub/Sub？ | Kafka 消息可持久化、可重放，消费组天然支持"每实例一份"的广播语义；Redis 只做缓存保持简单 |
| 读写分离怎么保证读到新数据？ | 登录等强一致场景 forceMaster 强制走主库；一般读允许最终一致 |
| 跨服消息怎么去重？ | Redis SETNX 去重键（from+to+时间戳），30 秒 TTL 覆盖重复窗口 |
| 如何水平扩展？ | 加一个容器+一个端口，SERVER_PORT 即 Kafka 消费组后缀，零代码改动 |
| 密码为什么是明文？ | 课程原型阶段权衡；升级方案：bcrypt/argon2 哈希 + 加盐（报告 3.1 已标注） |
| 单机能力如何？ | muduo Reactor + 4 IO 线程，千级并发连接；瓶颈在 MySQL 时靠缓存+读写分离缓解 |
